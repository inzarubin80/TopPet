# ТЗ: TopPet — конкурсы красоты животных

## 1) Термины
- **Конкурс (Contest)**: сущность, объединяющая участников, голосование, чат.
- **Участник (Participant / AnimalCard)**: карточка животного в рамках конкретного конкурса.
- **Голос (Vote)**: выбор пользователя в рамках конкурса (один на конкурс, действует последнее нажатие).
- **Комментарий (Comment)**: комментарий под карточкой участника.
- **Чат конкурса (ContestChat)**: общий чат в рамках конкурса.
- **Гость**: неавторизованный пользователь.
- **Пользователь**: авторизованный пользователь.
- **Админ конкурса**: пользователь, создавший конкурс.
- **Номинация**: **категория трека** внутри конкурса (например возрастная группа, техника, тема). Определяет, *в какой группе* участвует работа. Номинация — это не то же самое, что критерий оценки.
- **Критерии оценки (жюри)**: оси судейства (например композиция, техника, оригинальность), задаются **на уровне конкурса** и применяются **ко всем номинациям одинаково** (см. ниже).

## 2) Общие требования
- **Просмотр** конкурсов/участников/медиа/комментариев/истории чата не требует авторизации.
- **Любые изменения данных** (создание/редактирование/удаление) и **голосование** требуют авторизации.
- **Стек**:
  - Server: Golang.
  - Client: React.
  - DB: Postgres.
  - Работа с DB: SQLC.
  - Миграции: goose.
  - **FK в БД не используем** (целостность контролируем на уровне service).
  - Медиа: S3-совместимое Object Storage (Yandex Object Storage) + CDN base URL.
  - Чат: WebSocket hub + хранение истории в Postgres.
- **Ориентир реализации слоев/авторизации/S3/WS**: GreenWarden Server: `https://github.com/inzarubin80/GreenWarden/tree/main/Server`.

## 3) Жизненный цикл конкурса
Статусы:
- `draft`: черновик. Доступен только автору конкурса (включая прямую ссылку).
- `registration`: регистрация участников. **Голосование запрещено**.
- `voting`: голосование. **Голосование разрешено**.
- `finished`: завершён. **Голосование запрещено**.

Переходы:
- `draft -> registration -> voting -> finished`: только админ конкурса (поэтапно).

## 4) Номинации, критерии оценки и участники

### 4.1 Номинации
- Номинации задаёт организатор (черновик конкурса); лимиты по тарифу — в [`tier-matrix.md`](tier-matrix.md).
- Номинация — **категория**, а не критерий судейства: например «до 5 лет», «5–10 лет», «акварель» — это разные треки, а не «композиция» vs «колорит».

### 4.2 Критерии оценки (жюри)
- Критерии оценки задаются **на весь конкурс целиком** и **не привязываются к конкретной номинации** в модели предметной области.
- **Каждая номинация оценивается тем же набором критериев**, что и остальные: шкалы и названия критериев едины для конкурса; жюри выставляет баллы по этим осям в рамках выбранной для работы номинации (учёт победителей — по номинациям; сами оси оценки — общие).
- Отдельно: номинация отвечает на вопрос *в какой категории* работа; критерии — *по каким измерениям* оценивают качество работы.

### 4.3 Подача заявок и номинации
- При подаче заявки участник **выбирает номинацию**, если в конкурсе заведены номинации (иначе поле не используется).
- Один пользователь может подать **несколько работ** в одном конкурсе; типичный сценарий — **отдельная карточка участника (работа) на каждую номинацию**, в которой пользователь хочет участвовать (несколько номинаций → несколько заявок).
- Лимиты «не больше одной работы на номинацию на пользователя» или иные правила конкурса задаёт организатор и фиксируется в правилах/реализации при необходимости.

### 4.4 Карточка участника
- Пользователь может добавить неограниченное количество карточек животных в конкурс (в пределах бизнес-правил конкурса и номинаций).
  - Карточка содержит: `pet_name`, `pet_description`, при необходимости — выбранная **номинация**.
  - Медиа: 0..N фото, 0..1 видео (в MVP фиксируем 0..1, расширяемо).
- Редактирование карточки разрешено только владельцу карточки, при условии, что конкурс в статусе `draft` или `registration`.
- Удаление карточки разрешено только владельцу карточки, при условии, что конкурс в статусе `draft` или `registration`.
- При удалении участника удаляются все связанные данные: фото, видео, комментарии, голоса.

## 5) Голосование
- При голосовании **по номинациям** у пользователя **один выбор на номинацию** (внутри номинации повторный выбор заменяет предыдущий — upsert).
- Если номинации не используются, действует правило **одного голоса на пользователя в рамках конкурса** (актуальная конфигурация — в реализации).
- Голосование доступно только для `voting`.

### Ограничение видимости результатов
- Публично **не показываем рейтинг/расклад** по участникам.
- Пользователь видит:
  - свой текущий выбор (если авторизован),
  - агрегаты (например, `total_votes` у конкурса и/или у карточки без распределения).

## 6) Комментарии под карточкой
- Комментарии доступны всем для чтения.
- Писать комментарии могут только авторизованные пользователи.
- Комментарии доступны только в статусах `registration` и `voting`.
- Редактирование/удаление: только автор комментария (модерация админом конкурса — опционально, можно добавить позже).

## 7) Чат конкурса
- Чат существует у каждого конкурса.
- Чтение истории доступно гостям.
- Отправка сообщений — только авторизованным.
- Чат доступен в статусах `registration`, `voting`, `finished`.
- Реалтайм доставка новых сообщений: WebSocket.
- История хранится в Postgres с пагинацией.

## 8) Авторизация
- Access JWT (короткий TTL) + Refresh token (длинный TTL) по подходу GreenWarden.
- Auth required для всех mutating endpoints.
- Для WebSocket допускаем авторизацию через `Authorization: Bearer ...` или query `accessToken=...` (как в GreenWarden middleware).

## 9) Нефункциональные требования (MVP)
- Валидация входных данных (минимальные проверки: required, max length).
- Пагинация списков: конкурсы, комментарии, чат.
- Логи запросов на сервере.
- CORS на dev и whitelist в prod.
